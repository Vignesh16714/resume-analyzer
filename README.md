# 📄 AI-Powered Resume Analyzer

A Streamlit web app that extracts text from uploaded resumes (PDF/DOCX),
scores them for **ATS (Applicant Tracking System) compatibility** —
keyword match against a job description + formatting/structure quality —
stores every analysis in SQLite, and visualizes results with interactive
Plotly charts and animated radial gauges.

---

## ✨ Features

- Upload a resume as **PDF or DOCX** (with robust error handling for
  corrupt files, scanned/image-only PDFs, oversized files, wrong types).
- Paste a **job description** to get a targeted keyword-match score, or
  skip it to get a general score against a built-in technical skill list.
- **ATS structure score**: checks for section headings, contact info,
  bullet points, resume length, layout complexity, and a clear header.
- **Overall ATS score** = weighted blend of keyword match + structure.
- Human-readable **AI feedback & suggestions**, generated by a pluggable
  backend (see [Feedback backends](#-feedback-backends-ollama-vs-hugging-face) below).
- All analyses are **persisted to SQLite** (resumes + scores + feedback)
  for future reference.
- **Interactive results view**: animated ATS radial gauges (overall,
  keyword, structure) and a keyword coverage donut chart.
- **Skill Gap tab**: compare your resume against a custom job
  description, a curated role profile, or a specific tool/technology,
  with a coverage gauge and an estimated time-to-close by priority.

## 🎨 Visual theme

Styling lives in two places:

- **`.streamlit/config.toml`** sets Streamlit's native theme (page background,
  accent color, font) so built-in widgets (buttons, tabs, inputs) inherit
  the right look automatically.
- **`theme.py`** adds the rest: a bordered "card" container helper, colored
  progress bars, keyword badges/chips, and checklist status lines, all
  built from one `COLORS` dict so the palette only needs to change in one
  place.

Every text/background color pairing was checked against **WCAG AA contrast**
(4.5:1 for body text, 3:1 for large text/icons/borders) before being used.
Two of the requested colors needed a small adjustment to pass as *body
text on white* — this is documented in detail in the docstring at the top
of `theme.py`:

| Use | Color | Contrast on white |
|---|---|---|
| Primary text | `#111827` | 17.7:1 ✅ |
| Muted/secondary text | `#6B7280` | 4.8:1 ✅ |
| White text on accent blue button | `#FFFFFF` on `#2563EB` | 5.2:1 ✅ |
| Success **text** | `#047857` (darker than the requested `#059669`) | 5.5:1 ✅ |
| Success **fill/icon/border** | `#059669` (as originally requested) | 3.8:1 ✅ (meets the 3:1 bar for non-text) |
| Warning **text** | `#B45309` (darker than the requested `#D97706`) | 5.0:1 ✅ |
| Warning **fill/icon/border** | `#D97706` (as originally requested) | 3.2:1 ✅ (meets the 3:1 bar for non-text) |

If you want to change any color, re-check its contrast before shipping —
a one-line script for this is in the project's build notes; ping me if
you'd like it added as a `check_contrast.py` script.

## 🚀 Quickstart (local)

```bash
# 1. Clone / copy this folder, then create a virtual environment
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Download the spaCy model used for keyword extraction
python -m spacy download en_core_web_sm

# 4. Run the app
streamlit run app.py
```

The app opens at `http://localhost:8501`. Upload a resume, optionally
paste `sample_job_description.txt`'s contents into the job description
box, and click **Analyze Resume**.

> **No spaCy model? No problem.** `keyword_extractor.py` automatically
> falls back to a regex-based tokenizer if `en_core_web_sm` isn't
> installed, so the app still runs — just with slightly less precise
> keyword extraction. Run the download command above for best results.

## 🧠 Feedback backends: Ollama vs. Hugging Face

You asked which is better — **it depends on where you're running this**,
so the project supports **both**, plus a zero-dependency default:

| Backend | Set via `FEEDBACK_BACKEND=` | Best for | Trade-offs |
|---|---|---|---|
| `template` (default) | `template` | Fresh installs, CI, Hugging Face Spaces free tier | Deterministic, no ML downloads, always works — but less "natural" phrasing |
| `ollama` | `ollama` | **Local development** | Great, fast, free, private natural-language feedback — but needs a locally running `ollama serve` process, which most hosted Spaces **cannot** run alongside Streamlit |
| `huggingface` | `huggingface` | Hugging Face Spaces with enough RAM/CPU, or a GPU Space | Runs inside the same process/container as your Space — but slow cold starts and higher memory use (needs `transformers` + `torch`, uncomment them in `requirements.txt`) |

**Recommendation:** keep `template` as the default so the app "just
works" everywhere with zero setup. Use `ollama` locally while you
iterate (`ollama pull llama3` then `ollama serve`), and switch to
`huggingface` only if you deploy to a Space with enough resources and
want richer, LLM-generated prose.

To switch backends, either edit `config.py` or set an environment
variable before launching:

```bash
export FEEDBACK_BACKEND=ollama
export OLLAMA_MODEL=llama3
streamlit run app.py
```

Every backend call is wrapped in error handling — if Ollama isn't
running or a HF model fails to load, the app **automatically falls
back to the template backend** instead of crashing.

## 🧩 Example analysis workflow

1. User uploads `resume.pdf` and pastes a job description.
2. `utils.extract_text()` pulls raw text via PyMuPDF, `utils.clean_text()`
   normalizes whitespace.
3. `keyword_extractor.compute_keyword_match()` extracts JD keywords
   (spaCy noun-chunks + a built-in skills vocabulary) and checks which
   appear in the resume → **keyword score**.
4. `ats_scorer.score_structure()` runs 6 independent formatting/structure
   checks (sections, contact info, length, bullets, layout, header) →
   **structure score**.
5. `ats_scorer.compute_overall_score()` blends both (50/50 by default,
   tunable in `config.py`) → **overall ATS score**.
6. `llm_feedback.generate_feedback()` turns the scores + failed checks +
   missing keywords into a readable feedback paragraph.
7. `db.save_resume()` / `db.save_analysis()` persist everything to
   `resume_analyzer.db` (SQLite) for record-keeping.
8. Results render as animated radial gauges plus a keyword-coverage
   donut chart, followed by the checklist and AI feedback panel.

## 🗄 Database schema

```sql
CREATE TABLE resumes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    filename TEXT NOT NULL,
    raw_text TEXT NOT NULL,
    uploaded_at TEXT NOT NULL
);

CREATE TABLE analyses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    resume_id INTEGER NOT NULL,
    job_description TEXT,
    ats_score REAL NOT NULL,
    keyword_score REAL NOT NULL,
    structure_score REAL NOT NULL,
    matched_keywords TEXT,
    missing_keywords TEXT,
    feedback TEXT,
    created_at TEXT NOT NULL,
    FOREIGN KEY (resume_id) REFERENCES resumes (id)
);
```

## 🔌 Extending with LangChain

`langchain` is included in `requirements.txt` as a hook for orchestration
if you want to grow this into a multi-step agentic pipeline later — for
example, chaining: *extract → summarize → score → generate feedback →
suggest rewritten bullet points*, each as a LangChain `Runnable`. The
current pipeline is implemented directly in `app.py` for clarity and
speed; swap in a LangChain `SequentialChain`/LCEL pipeline around
`keyword_extractor`, `ats_scorer`, and `llm_feedback` if you need more
complex branching, memory, or multi-model routing.

## ☁️ Deployment to Hugging Face Spaces

1. Create a new Space at https://huggingface.co/new-space, choose
   **Streamlit** as the SDK.
2. Push these files to the Space's repo (`app.py` must stay at the repo
   root — Spaces auto-detects and runs it).
3. Make sure `requirements.txt` is present — Spaces installs it
   automatically on build. Add this line so the spaCy model downloads
   during the build (Spaces has no interactive shell):
   ```
   https://github.com/explosion/spacy-models/releases/download/en_core_web_sm-3.7.1/en_core_web_sm-3.7.1-py3-none-any.whl
   ```
   (append it to `requirements.txt` — pip installs wheels from URLs directly).
4. Leave `FEEDBACK_BACKEND=template` (the default) unless your Space has
   enough resources for `huggingface` — see the table above.
5. SQLite (`resume_analyzer.db`) is written to the Space's ephemeral
   filesystem. This is fine for demos, but **data will reset on
   Space restarts/rebuilds**. For persistent storage in production,
   swap `db.py`'s `sqlite3` connection for a hosted database (e.g.
   Postgres via `psycopg2`) — the rest of the app is unaffected since
   all DB access goes through `db.py`'s small function API.

### Alternative hosting
This is a plain Streamlit app with no Spaces-specific code, so it also
deploys unmodified to **Streamlit Community Cloud**, **Render**,
**Railway**, or any Docker host — just run
`streamlit run app.py --server.port $PORT --server.address 0.0.0.0`.

## ⚠️ Error handling included

- Wrong file type (not PDF/DOCX) → clear `st.error()`, no crash.
- Empty file / oversized file (>5MB, tunable in `config.py`) → rejected early.
- Scanned/image-only PDFs (no extractable text) → explicit message
  suggesting a text-based PDF or DOCX instead.
- Corrupt/unreadable PDF or DOCX → caught and re-raised as a friendly
  `ResumeParsingError` message.
- Missing spaCy model → automatic fallback to regex tokenizer.
- Ollama/Hugging Face feedback backend unreachable or erroring →
  automatic fallback to the deterministic template backend.

## 🛠 Configuration reference (`config.py`)

| Variable | Default | Purpose |
|---|---|---|
| `DB_PATH` | `resume_analyzer.db` | SQLite file location |
| `MAX_FILE_SIZE_MB` | `5` | Reject uploads larger than this |
| `FEEDBACK_BACKEND` | `template` | `template` / `ollama` / `huggingface` |
| `WEIGHT_KEYWORD_MATCH` / `WEIGHT_STRUCTURE` | `0.5` / `0.5` | Overall score blend |
| `MIN_RESUME_WORDS` / `MAX_RESUME_WORDS` | `150` / `1200` | Length check thresholds |
| `EXPECTED_SECTIONS` | Experience, Education, Skills, ... | Section-heading check |
| `DEFAULT_SKILL_VOCAB` | ~40 common tech/soft skills | Fallback keyword universe when no JD given |

All are overridable via environment variables of the same name (see
`config.py` for the `os.getenv(...)` calls).
